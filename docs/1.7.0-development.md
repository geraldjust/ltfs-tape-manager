# LTFS Tape Manager 1.7.0 — development specification

This branch is **not a production release**. Keep the 1.6 branch and v1.6.9 image unchanged until the complete feature set is tested.

## Write options
- Default: source read once, SHA-256 generated during sequential tape write; committed tape read once after clean unmount and read-only remount for independent SHA-256 comparison.
- Optional dual-pass: same sequence plus **second source read** after tape remount to independently SHA-256 compare the original source to the tape-verified digest. This is slower. A second source read does not substitute for reading the tape.
- Optional TAR packaging checkbox, disabled by default for compatibility.
- Configurable individual-file threshold; default **16 MiB**. Files strictly smaller qualify; larger files remain individual LTFS files.
- Configurable maximum TAR archive size, default **32 GiB**, with smaller choices (1, 2, 4, 8, 16 GiB).
- Group files **only by their immediate parent folder**. Never combine files across folder levels. Preserve original paths in a sidecar manifest.
- TAR is uncompressed in v1.7.0 (packaging, not compression); no on-disk staging of whole archives. Archive size includes TAR headers, padding and end-of-archive blocks. Split groups deterministically at configured size.
- Reserve collision-free tape paths for archives, manifests, and direct files before writing. Existing tape entries are never overwritten.
- Source file changes during archive streaming must fail the job; archive and manifest commit only after all expected members have been successfully streamed and hashed.

## Archive manifest and read browser
- Manifest on tape records schema version, archive relative path, member relative path, original size, SHA-256, and member ordering. Store manifest atomically as part of LTFS write/commit.
- The Read tab shows each TAR file as a real tape file, expandable using its manifest. Browsing should not scan archive data.
- Warn: restoring any selected member may require streaming the **entire archive** from tape.
- Restore whole archive or selected members into a fresh destination directory. Reject absolute paths, traversal, symlinks, hardlinks, devices, duplicate output names and unsafe metadata; never extract TAR via unrestricted shell.
- Stream archive once for multiple selected members. Verify archive SHA-256 against the committed tape manifest, and member SHA-256 after extraction.
- Missing/corrupt manifests must not silently present a trustworthy virtual folder.

## Validation gates
- Single-pass direct file, dual-pass direct file, TAR single-pass, TAR dual-pass.
- Empty files, unusual filenames, nested directories, mixed sizes, split boundaries, 32 GiB edge, duplicate tape names.
- Failed source reads, changing sources, premature write failure, failed clean commit, failed read-only mount, wrong SHA-256, interrupted restore.
- Verify 100% on small controlled test tape before publishing v1.7.0 image or changing production YAML.
